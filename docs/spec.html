0 The rules

  • Plan limits come only from the documented Claude Code status line feed. Tokens come only from the local transcripts. Mac figures come only from public macOS calls.
  • No Keychain item, credential, token or undocumented endpoint is read, ever, not even behind an opt in. Anthropic's legal page bars developers from collecting, storing or intermediating Claude.ai credentials or session tokens, verbatim, and reserves enforcement without notice.
  • No network call of any kind. No analytics, crash reports, update check or price fetch.
  • The product name does not contain "Claude", "Claude Code" or "Anthropic": the legal page bars their use "as part of your own product, feature, or company name". It allows saying in plain text that something runs Claude Code, so the UI says "Claude Code" as a fact.
  • Anthropic's terms say nothing either way about a local tool reading the transcripts or the status line feed; the status line documentation describes the feed as input for "any shell script you configure". That is silence, not permission, and the README says so.
  • The app reads only the fields named in this spec and drops the rest of every line. What it must never read is listed in section 5 and on the privacy page.

1 Architecture

  • Swift Package Manager only. No Xcode project. A package with swift-tools-version 6.0, platform macOS 14, seven library targets, one executable target tokenpanda linking AppKit, IOKit and UserNotifications, and one test target tokenpandaTests. Proven on the build Mac (Command Line Tools only, Swift 6.4, SDK 27.0): a status item plus popover package builds in 32 s with swift build -c release; SwiftPM signs the product ad hoc by itself. xcodebuild is not needed and not available there.
  • Minimum macOS 14. The widest floor among the AI usage meters; the package declares it. Apple silicon first; a universal binary is a release option, untested until someone tests it.
  • AppKit status item. NSStatusBar.system.statusItem(withLength: .variableLength) with a custom NSView in the item's button that draws the digits and the 5 cell bar and marks itself dirty when a value arrives; no redraw timer. SwiftUI's MenuBarExtra is not used: no custom view in the item, no fade on dismiss, no persisted selection.
  • NSPopover anchored to the item, 380 by 420 points, with an NSVisualEffectView for the glass and an NSHostingController root; the content is SwiftUI text views rendering the lines the Text module produces, or an AppKit text view, the builder's choice. The popover is one monospaced layout of lines, not controls stacked in a grid.
  • Activation policy accessory (NSApp.setActivationPolicy(.accessory)) and LSUIElement true in Info.plist: no Dock icon, no app menu.
  • Not sandboxed. The transcript reader needs ~/.claude, the process list needs libproc, and the hook lives in Application Support. The entitlements file is empty.
  • No dependencies outside the SDK.
  • Swift 6 language mode with strict concurrency: the samplers and readers are actors, the UI state is one main actor observable.

3 The status line hook

The only source of plan percentages, verified on a Mac on 2026-10-13 against the documentation and a live capture.

How Claude Code runs it

  • Configured under the statusLine key of ~/.claude/settings.json: type is "command", command is a script path or an inline shell command, and the optional refreshInterval re-runs the command every N seconds (minimum 1) in addition to the events.
  • The script runs once when a session starts or resumes, then after each assistant message, after /compact, on permission mode and vim mode changes, when the command setting changes, when a timer elapses, and when a rate limit window in the last data reaches its resets_at. Updates are debounced at 300 ms; an in-flight script is cancelled when a new update triggers.
  • The first call of a session never carries rate_limits; every later call does (38 of 38 in the capture). With refreshInterval the timer fires while the session sits idle too. Between sessions the feed stops.
  • The feed reflects the account, not the one session: with two sessions open, both report the same account windows and the values move together.
  • Per session override for testing: claude --settings '{"statusLine":{"type":"command","command":"/path/hook.sh"}}' changes nothing on disk.

There is no per model field and no plan tier field; the popover carries no tier badge.

The hook script

One job: copy stdin to a snapshot file, atomically, then hand the same input to the status line command the user had before, if any. It parses nothing, so it needs no jq, no python, nothing but sh.

#!/bin/sh
# The status line hook. Copies the feed Claude Code hands it to one file per session, atomically,
# then hands the same input to the status line command that was configured before, if any.
# It parses nothing and needs nothing but sh. The app fills in DIR and PREV at install time.
DIR="__DIR__"                 # filled in at install: the sessions folder in Application Support
PREV='__PREV__'               # filled in at install: the previous statusLine command, or empty
input=$(cat)
sid=$(printf '%s' "$input" | sed -n 's/.*"session_id":"\([0-9a-fA-F-]*\)".*/\1/p' | head -n 1)
mkdir -p "$DIR"
if [ -n "$sid" ]; then
  printf '%s' "$input" > "$DIR/$sid.json.tmp" && mv -f "$DIR/$sid.json.tmp" "$DIR/$sid.json"
else
  printf '%s' "$input" > "$DIR/latest.json.tmp" && mv -f "$DIR/latest.json.tmp" "$DIR/latest.json"
fi
if [ -n "$PREV" ]; then printf '%s' "$input" | sh -c "$PREV"; fi
exit 0
  • refreshInterval is set to 5, when the user's entry has none of its own, so the open sessions list and the reset rollover stay current while a session idles; the capture ran at 2 s with no visible cost. The script prints nothing of its own, so a user without a status line sees nothing new, and a user with one sees it unchanged.
  • The snapshot is the whole feed JSON as received. The app reads only the fields in the table above. The file is overwritten on every call and deleted by the app 60 s after its last write; the folder is removed on uninstall.
  • Installing means editing the user's ~/.claude/settings.json. The app does this only on an explicit click, on "Install the status line hook" on the Claude tab or "Install the status line entry" in Settings. It keeps a previous command by chaining it, keeps the other keys of an existing statusLine object (padding, the user's refreshInterval), adds refreshInterval 5 only when there is none, and saves the object as it was to statusline-before.json in Application Support. The file is parsed, the statusLine key replaced, and the whole file written back by JSONSerialization pretty printed with slashes unescaped: indentation and key order may change, the content of every other key does not.
  • Removing is the Settings row "Remove the status line entry", one explicit click. While the entry is still the app's, the saved object goes back exactly as it was, or the key is removed when there was none; an entry the user changed in the meantime is left alone. The script, the saved object and the sessions folder are deleted. settings.json is otherwise off limits; the app reads its modification time each feed tick and reads the file again only when that time moves.
  • An install or remove error is shown under the Settings row and written to the unified log, the message marked private.
  • The session_id extraction above assumes the key appears as "session_id":"…" without whitespace, as in the capture; the installer verifies it on the first feed and falls back to a single latest.json if the pattern does not match.

Staleness

  • The newest snapshot file sets the windows. Its modification time is the snapshot time, shown as "Usage as of HH:MM, last Claude Code session" in the header when no session has fed in the last 60 s; while one has, the header says "Usage live".
  • A snapshot younger than one hour: live. Pace lines are computed.
  • Older than one hour: stale. The bar drops to the track colour, the percent and tick go dim, "as of HH:MM" replaces the pace lines, the menu bar item dims to 50%, and the Claude tab adds "Limits are shared across Claude and Claude Code, so use elsewhere moves these figures." Nothing is projected from old data. Claude Code itself keeps a 60 minute last known usage when its own request fails; the hour matches it.
  • A window whose resets_at has passed while stale is shown as the stale form with "reset passed HH:MM" in place of the reset line, because the window has rolled and the feed will carry the new one at the next session.
  • A snapshot without rate_limits (the first call of a session) never replaces the windows; the app keeps the previous values and waits for the next call.

Window length

The feed names its windows and gives resets_at, not a length. The length comes from the key name: five_hour is 5 h, seven_day is 168 h. The start is resets_at minus that length. The app checks the length against the observed distance between two consecutive resets_at values of the same key once it has seen two, and if they disagree, or if a key it does not know appears, it shows the window's percent with "unknown window" in place of the pace lines and never guesses.

4 Open sessions

Every running Claude Code session fires its own feed, so the app knows which sessions are open. One snapshot file per session_id (section 3). A session is open when its file was written in the last 10 s; it leaves the list 60 s after its last write and its file is deleted then.

  • Section "Open sessions" on the Claude tab, after the two windows. One entry per open session: the project folder's last path segment in bold, the model name dim, the context figure "405.6k of 1M" dim at the right; under it a 36 cell bar of context_window.used_percentage with " 41% used". No tick: the context is a share, not a time window.
  • The figure's tooltip: "USD 38.20 list price equivalent 112 added 9 removed", from cost.total_cost_usd, total_lines_added, total_lines_removed; the effort level is appended when present.
  • The context figure is current_usage's four counts summed, formatted as k or M, over context_window_size formatted as k or M ("1M"). When current_usage is null (first call), the entry shows the project and model and an empty bar with "waiting for the first reply".
  • Sorted by context used, largest first; at most five, then "and N more" dim.
  • No open session: the section is omitted. Stale: omitted.

Not available by the rules and never drawn: the context breakdown by category (messages, system tools, memory files, skills, MCP) and the per MCP tool token counts that Claude Code shows in its own usage screen. Those are computed inside Claude Code and are in neither the feed nor the transcripts.

5 The transcript reader

Paths

  • ~/.claude/projects/<project>/<session>.jsonl for a session; ~/.claude/projects/<project>/<session>/subagents/agent-<id>.jsonl for its subagents (a sibling agent-<id>.meta.json is not read). The project folder is the absolute working directory with every slash replaced by a dash. The session id is the file name without .jsonl; every line inside carries sessionId equal to it.
  • Also ~/.config/claude/projects, and the directories in CLAUDE_CONFIG_DIR when set (ccusage reads these; comma separated).
  • Only *.jsonl at depth 1 under a project and under subagents/. Files modified in the last 32 days; the windows need 30.
  • Documented retention: "Claude Code clients store session transcripts locally in plaintext under ~/.claude/projects/ for 30 days by default to enable session resumption. Adjust the period with cleanupPeriodDays." So the 30 day figure depends on that setting. No published schema; one session file can mix Claude Code versions (2.1.278 to 2.1.294 in one file); the parser skips any line it cannot read.
  • Streaming, line by line: one file on the build Mac was 371 MB and 40483 lines. Never load a whole file.

Fields read per line, and nothing else

The parser decodes these keys and drops the rest of the line. It never reads message.content, toolUseResult, attachment, snapshot, or the account keys accountUuid, ownerAccountUuid, ownerOrganizationUuid, bridgeSessionId. The usage object's other keys (thinking tokens, server tool use, service tier, speed, iterations) are not used.

What the app must never open

  • ~/.claude/projects/<project>/memory/: personal notes in Markdown. Not transcripts.
  • ~/.claude/projects/<project>/<session>/tool-results/: tool outputs and hook output with file contents, images and PDFs.
  • <session>/custom-title.json, auto-mode-classifier-error.txt, the agent-<id>.meta.json files.
  • Elsewhere in ~/.claude, by name: history.jsonl, stats-cache.json, sessions/, state/, uploads/, daemon/, paste-cache/, file-history/, and settings.json except the one statusLine key the installer edits with consent.

The reader enumerates only the two patterns in "Paths" and never walks a directory recursively.

Dedupe

Claude Code writes one assistant line per content block (thinking, text, tool use), each carrying the same message.id and the same usage. On the build Mac: 5926 assistant lines for 3679 distinct ids, one id up to eleven times; the naive sum of output_tokens was 2.45 times the true figure. Rule: keep the last line per message.id; the usage is identical across repeats. message.id and requestId are one to one (3679 of each), so the request id is a cross check only.

Reading cadence

  • Full pass on launch and every 300 s. Files modified since the last pass are read from their last byte offset every 10 s while the popover is open.
  • On an actor off the main thread; the UI gets a finished aggregate.

7 The pace model

Four inputs per window: used percentage U, window start S (resets_at minus the length named by the key), reset R, now T.

elapsed    = T - S                       (hours)
remaining  = R - T                       (hours)
E          = elapsed / (R - S) × 100     (elapsed share, percent)

status     = Over pace  when U > E + 5
             Ahead      when U < E - 5
             On pace    otherwise

rate       = U / elapsed                 (percent per hour)
to_limit   = (100 - U) / rate            (hours)
projection = if to_limit < remaining:  "limit " + clock(T + to_limit) + " at this rate"
             else:                      round(U + rate × remaining) + "% by reset at this rate"
allowance  = (100 - U) / remaining       (percent per hour) + "% an hour left"
countdown  = remaining as "in Nd Nh" or "in Nh Nm"
  • The projected clock time is rounded to five minutes; the weekly form carries the weekday, the 5h form does not.
  • The allowance prints one decimal under 1% and whole numbers from 1%.
  • The tick on the bar stands at E. The fill past the tick is coral only when the status is Over pace.
  • Stale windows compute nothing; a window with U = 0 has no rate and prints no projection; an unknown window (section 3) prints "unknown window".

8 The Mac sampler

Every call is a public Mach, sysctl, IOKit or libproc call made in process; no tool is spawned, no root, no entitlement. All of them were run from an unsigned binary on the build Mac on 2026-10-13. Intervals and budget

  • Popover open: every 2 s, all figures, the process table included. Measured: sampling everything every 2 s, every process' rusage included, costs 0.40% of one core (getrusage(RUSAGE_SELF) over 60 s, 4.5 to 5.1 ms per sample).
  • Popover closed: every 10 s, CPU totals, pressure, and one libproc pass for the warning rule; below 0.1% of a core by the same measure. GPU and battery are not sampled while closed unless "Mac figures in the bar" is on.
  • Timers are DispatchSourceTimer on a utility queue with a leeway of 10% of the interval.

The Mac warning rule

Memory pressure warn or critical, or one process over 80% CPU for 60 s, timed by the clock from the first sample that saw it, so the rule is the same at the 2 s and the 10 s cadence. While it holds: the Mac tab gets the ● dot, the menu bar item appends ⚠. The Mac figures themselves stay off the menu bar unless the setting is on.

9 Notifications

  • Two nudges, through the macOS notification centre, as banners the OS draws. No sound, no icon beyond what the OS adds.
  • "Weekly at 80%" with "2 days 4 h to the reset. At this pace the limit lands Saturday 09:00." Fires once per weekly window when the snapshot first shows 80% or more and is not stale. The body is built from the pace model: the countdown as days and hours, then the projection sentence.
  • "5h window ends in 15 min" with "34% used." Fires once per 5h window, 15 minutes before resets_at, only if a snapshot younger than an hour exists.
  • Both behind the Settings row "Nudge at 80% and before the 5h end", on by default. The first time it is on, the app asks for notification permission; if denied, the row's second line says so.
  • Framework: UserNotifications (UNUserNotificationCenter). to be verified: that notification permission can be requested from an app bundle assembled by script without an Xcode project; neither the research nor the verification run covers it. If it cannot, NSUserNotification is the fallback (deprecated, still present).

15 Logging

No log file. Errors are shown in the popover in the states above. One kind of error also goes to the macOS unified log: a failed install or removal of the status line entry, under the subsystem dev.tokenpanda.app, with the message marked private. A debug build may print to stdout; a release build prints nothing.

16 Updates

No update mechanism in the app: no Sparkle, no appcast, no version check against GitHub. Releases are published on GitHub Releases; the Homebrew tap's cask carries the version, and brew upgrade updates it. Users who download the zip check the releases page themselves. This is what keeps the network call count at zero.

17 Packaging

Build

scripts/build-app.sh 0.1.0   # swift build -c release, then build/tokenpanda.app: Contents/MacOS,
                             # Contents/Resources (hook.sh), Info.plist (LSUIElement true), ad hoc codesign;
                             # then build/tokenpanda-0.1.0.zip and its SHA-256

Two release paths. Releases are built by path one for now; path two is written here for when the project signs with a Developer ID.

Path one: unsigned (ad hoc), own tap

Ad hoc signing does not satisfy Gatekeeper on a downloaded file, and since macOS Sequoia Control-click no longer overrides it. Apple's current page (published 2026-05-27) gives the flow, which the README repeats:

  1. Try to open the app.
  2. Open System Settings, click Privacy & Security, scroll down, and click the Open Anyway button.
  3. The warning reappears; click Open. The app is now saved as an exception and opens by double click from then on.

Apple's page names Catalina and later and Sequoia; it does not name macOS 26 or 27, so it is Apple's current page rather than a version specific statement. Removing the quarantine attribute with xattr is a community workaround and is not in the README.

Homebrew's main cask repo requires that artefacts "must pass Homebrew's Gatekeeper checks", and support for failing casks ended on 2026-09-01, so an unsigned app lives in its own tap: the repository tokenpandadev/homebrew-tap, with a Casks directory at the top level holding tokenpanda.rb (the template is in this repository under Casks/); users run brew install tokenpandadev/tap/tokenpanda. No notability rule applies to a tap; "Non-official taps require explicit trust by default". The Open Anyway flow still applies after a brew install.

Path two: Developer ID and notarisation

  • Apple Developer Program, 99 USD a year, includes the Developer ID certificate; no fee waiver for an individual.
  • Sign with Developer ID, hardened runtime (codesign --options runtime), a secure timestamp, no get-task-allow; xcrun notarytool submit app.zip --keychain-profile <profile> --wait; xcrun stapler staple tokenpanda.app. 75 notarisations a day; most finish within five minutes. Stapled, Gatekeeper needs no online check and the user sees no warning.
  • GitHub Actions: free for a public repository; the macos-26 image is macOS 26 on Arm64 with Xcode 26.6 by default. Secrets: the base64 .p12, its password, an App Store Connect API key, the team id; a temporary keychain; build, sign, notarytool, stapler, release.
  • The main Homebrew cask repo then becomes possible once the repo meets its notability rule: "at least 30 forks, 30 watchers or 75 stars", "at least 90 forks, 90 watchers or 225 stars for a self-submission by the repository owner", and not under 30 days old. Until then the own tap serves notarised builds too.

19 Test plan

Unit tests, in the package

  • Pace model: the worked example of section 7 as fixtures, both branches; the three status words at the thresholds (U = E + 5 is On pace, U = E + 5.01 is Over pace); U = 0; T past R; an unknown key yields "unknown window"; a second resets_at that contradicts the key's length yields "unknown window".
  • Feed parser: the captured sample JSON (percentages as integers) and the doc example (23.5) both parse; a first call without rate_limits leaves the windows untouched; unknown keys such as scratchpad_dir are ignored; session_id, project_dir, model, context_window and cost are read; current_usage null is handled.
  • Open sessions: a file written 9 s ago is open, 11 s ago is not, 61 s ago is deleted.
  • Bar builder: 36 cells at 61% is 21 full cells and a full block (22 cells); 50 cells at 9% is four full cells and ▌; the tick at E = 55% of 36 is cell 20; the tick never exceeds N - 1; stale yields no coral.
  • Transcript reader: a fixture transcript with one message id written three times with identical usage sums it once; a <synthetic> line is skipped; a malformed line is skipped; a file under subagents/ and a line with isSidechain true count as agent share; a file under memory/ or tool-results/ is never opened (the enumerator is tested against a fixture tree); the sum matches the fixture's cost-state line within rounding.
  • Prices: one message per row of the table against a hand computed figure; an unknown id counts tokens and no cost; the Haiku 5.5 tier by input size; the 5m and 1h split.
  • Text renderer: every component of the style guide against a golden string, so a change to the grammar is visible in a diff.

By hand, before a release

  • Install the hook on a Mac with no status line and on one with an existing status line; confirm the existing one still renders and settings.json keeps its other keys.
  • Start a Claude Code session; confirm "Usage live" after the first reply and the open session row; quit the session; confirm the row leaves after 60 s and "Usage as of HH:MM, last Claude Code session" appears; set the clock forward an hour and confirm the stale form.
  • Open Anyway flow on a clean user account (path one), or a clean Gatekeeper pass (path two).
  • Reduce motion on: no animation. VoiceOver: every label of the style guide's table reads as written.
  • Light and dark menu bar; a Mac on battery; a desktop Mac without a battery; a Mac without the capacity keys ("health n/a").
  • macOS 26 and later: System Settings, Menu Bar, the app must be allowed or its item does not show.
  • CPU budget: with the popover closed, read the app's CPU in Activity Monitor over ten minutes; the average must be under 0.5% of one core. With it open, under 2%.
  • Network: run with Little Snitch or nettop filtered to the app for an hour; the count of connections must be zero.
